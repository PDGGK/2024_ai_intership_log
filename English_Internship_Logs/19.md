## Background

Today I worked on understanding and extending the scene analysis system architecture. The system combines Vision-Language (VL) models for image understanding with LLMs for text analysis.

---

## System Architecture

```plaintext
Request → FastAPI Router → Scene Handler → VL Model → LLM → Response
                                ↓
                          File Processing
                          (Image/PDF)
```

Core components:
- **VL Model**: Extracts text and visual information from images
- **LLM Model**: Analyzes extracted text, makes judgments
- **Scene Module**: Implements specific business logic for each use case

## Scene Development Pattern

Each scene follows a standard structure:

1. **Define Response Model**: What data does this scene return?
2. **Configure Prompts**: What instructions go to VL and LLM?
3. **Implement Handler**: Business logic for processing
4. **Register Route**: FastAPI endpoint
5. **Write Tests**: Validation of expected behavior

## Processing Flow

```python
class DocumentAnalysisHandler:
    async def process(self, file: UploadFile) -> DocumentAnalysisResponse:
        await check_file_size(file)

        content = await file.read()
        if file.filename.endswith('.pdf'):
            images = convert_pdf_to_images(content)
            results = [await self._process_image(img) for img in images]
            return self._combine_results(results)
        else:
            image = Image.open(BytesIO(content))
            return await self._process_image(enhance_image(image))

    async def _process_image(self, image):
        text = await recognizeImageTextVL(image, prompt="...")

        return extract_and_format_json(analysis)
```

## Today's Reflection

The scene-based architecture is elegant. Each scene is self-contained with its own configuration, prompts, and handlers. Adding a new analysis type doesn't require touching existing code - just add a new scene module.

The VL + LLM pipeline makes sense for document analysis. The VL model handles the "perception" task (reading text from images), while the LLM handles "cognition" (understanding and reasoning about the text). Separating these concerns allows each model to be optimized for its task.

One thing I'd improve: the current design couples scene logic with API routes. A cleaner approach would be a scene registry that automatically generates routes from scene definitions.
