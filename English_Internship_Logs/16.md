# Cross-Platform Python Deployment in Virtual Machines

> **Date**: 2024-12-01
> **Topic**: ARM VM deployment, cross-platform dependencies, and network configuration

---

## Background

Today I deployed a Python project on an Ubuntu ARM virtual machine running on my M1/M2 Mac. This introduced several cross-platform challenges.

---

## Cross-Platform Dependency Issues

**Problem**: Windows-specific packages fail on Linux.

```bash
ERROR: Could not find a version that satisfies the requirement pywin32==308
ERROR: No matching distribution found for pywin32==308
```

**Solution**: Remove platform-specific packages before installation:

```bash
# Filter out Windows packages from requirements.txt
sed -i '/pywin32/d' requirements.txt
pip install -r requirements.txt
```

---

## Missing System Dependencies

**Problem**: PDF processing failed with poppler error.

```bash
Unable to get page count. Is poppler installed and in PATH?
```

**Solution**: Install system-level dependencies:

```bash
sudo apt-get update
sudo apt-get install -y poppler-utils
```

## Understanding System Layers

A useful mental model for dependency management:

```plaintext
System Architecture
├── Operating System Layer
│   ├── System Tools (poppler, ffmpeg, etc.)
│   └── System Libraries
├── Python Environment Layer
│   ├── Virtual Environment (.venv)
│   └── Python Packages (pip)
└── Application Layer
    ├── Your Code
    └── Configuration
```

System tools like poppler are infrastructure - they exist outside Python's virtual environment and must be installed via apt/brew.

## Python Environment Management

```bash
# Create and activate virtual environment
python -m venv venv
source venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Deactivate when done
deactivate
```

## Today's Reflection

Today clarified the distinction between **Python packages** and **system dependencies**. It's easy to assume everything goes in requirements.txt, but some dependencies (like poppler for PDF processing) are native binaries that must be installed at the OS level.

The cross-platform issue was predictable in hindsight. Requirements files often accumulate platform-specific packages over time. When migrating to a different OS, these need to be filtered out. A better approach would be using conditional dependencies in the first place.

The ARM VM added another layer of complexity - even some native packages may not have ARM builds. Fortunately, poppler supports ARM64 well on Ubuntu.
