## The Problem

The system was attempting to allocate 254GB of GPU memory on a 79GB GPU:

```
CUDA out of memory. Tried to allocate 254.00 GiB.
GPU 0 has a total capacity of 79.11 GiB of which 14.88 GiB is free.
```

Root causes:
- No memory monitoring before inference
- Multiple processes competing for GPU
- No graceful degradation strategy

## Memory Management Solution

```python
class MemoryManager:
    def __init__(self, threshold=0.8):
        self.threshold = threshold
        self.allocated = {}

    async def check_memory(self) -> bool:
        try:
            total, used, free = torch.cuda.mem_get_info()
            usage = used / total
            logger.info(f"GPU: {used/1024**3:.2f}/{total/1024**3:.2f} GB ({usage:.1%})")
            return usage < self.threshold
        except Exception as e:
            logger.error(f"Memory check failed: {e}")
            return False

    def release(self, purpose: str):
        if purpose in self.allocated:
            del self.allocated[purpose]
            torch.cuda.empty_cache()
            gc.collect()
```

## Batch Processing with Dynamic Sizing

```python
class BatchProcessor:
    def __init__(self, memory_manager):
        self.memory_manager = memory_manager
        self.batch_size = 1  # Start conservative

    async def process_batch(self, items, processor):
        results = []
        current_batch = []

        for item in items:
            current_batch.append(item)

            if len(current_batch) == self.batch_size:
                if not await self.memory_manager.check_memory():
                    # Reduce batch size on memory pressure
                    self.batch_size = max(1, self.batch_size - 1)

                try:
                    batch_results = await processor(current_batch)
                    results.extend(batch_results)
                except torch.cuda.OutOfMemoryError:
                    # Fallback to individual processing
                    for single in current_batch:
                        result = await processor([single])
                        results.extend(result)
                        torch.cuda.empty_cache()

                current_batch = []
                await asyncio.sleep(0.1)  # Brief pause

        return results
```

## Framework Limitation

xinference only supports batching for specific VL models:
- qwen-vl-chat
- cogvlm2
- glm-4v
- MiniCPM-V-2.6

Our model (Qwen2-VL-7B-Instruct) wasn't on the list, requiring single-item processing.

## Error Recovery Handler

```python
class ErrorRecoveryHandler:
    async def handle_error(self, error, context):
        if isinstance(error, torch.cuda.OutOfMemoryError):
            torch.cuda.empty_cache()
            gc.collect()
            await asyncio.sleep(1.0)
            context['batch_size'] = 1
            return await self._retry_operation(context)
        elif isinstance(error, json.JSONDecodeError):
            return await self._handle_json_error(context)
        else:
            return await self._handle_general_error(context)
```

## Today's Reflection

GPU memory management in production is harder than expected. The 254GB allocation attempt was clearly a bug - no single image should require that much memory. The issue was likely unbounded tensor accumulation.

The key lessons:
1. **Always monitor before allocating** - check available memory before inference
2. **Start small, scale up** - begin with batch_size=1 and increase if memory allows
3. **Graceful degradation** - when batching fails, fall back to single-item processing

The xinference limitation was frustrating but educational. Framework constraints are real and need to be worked around.
