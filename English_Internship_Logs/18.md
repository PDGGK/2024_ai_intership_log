## Server Listening Configuration

Understanding the difference between listening addresses:

```python
def run_api_server():
    host = "0.0.0.0"  # Listen on all interfaces
    port = 9001
    uvicorn.run(app, host=host, port=port)
```

| Address | Behavior | Accessibility |
|---------|----------|---------------|
| `0.0.0.0` | All network interfaces | Remote + local |
| `127.0.0.1` | Loopback only | Local only |
| Specific IP | That interface only | Depends on network |

For development servers that need to be accessed from other machines (like your host Mac accessing a VM), use `0.0.0.0`.

## Troubleshooting 404 Errors

When getting 404 on an API endpoint:

1. **Verify route registration** - Is the route decorator applied?
2. **Check URL path** - Trailing slashes matter
3. **Confirm server restart** - Code changes require restart
4. **Review logs** - Server logs show registered routes at startup

## Git Merge Conflict Resolution

On the remote server, I encountered merge conflicts when pulling updates:

```bash
# Configure git user (required for commits)
git config --global user.email "your@email.com"
git config --global user.name "Your Name"

# View conflict status
git status

# Edit conflicting files
vim <filename>

# After resolving, commit
git add <files>
git commit -m "Resolve merge conflicts"
```

## Today's Reflection

Today's issues were "obvious in hindsight" problems. The 404 was simply a missing route registration - the endpoint was defined but not included in the router. The git conflicts were straightforward once I understood the workflow.

The key insight: **development and deployment are different contexts**. Code that runs fine in VSCode may fail in a VM due to different paths, permissions, or configurations. Testing in a production-like environment catches these issues early.

I'm also more appreciative of proper git workflows now. On a remote server, you can't just "fix it later" - you need to resolve conflicts properly to continue.
