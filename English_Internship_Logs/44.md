# Pydantic-Based Rule Model Design

> **Date**: 2024-01-30
> **Topic**: Type safety and data validation for rule parsing

---

## Background

Today I implemented Pydantic models for the rule parsing system. Pydantic provides runtime type checking and validation, which is essential for data coming from LLM outputs.

---

## Why Pydantic?

1. **Runtime validation**: Catches invalid data immediately
2. **Type coercion**: Automatically converts compatible types
3. **IDE support**: Autocomplete and type hints work
4. **JSON Schema**: Auto-generated for documentation

## Validation Configuration Model

```python
class ValidationConfig(BaseModel):
    tool: ToolType = Field(..., description="Validation tool name")
    check: str = Field(..., min_length=1, description="What to check")

    class Config:
        json_schema_extra = {
            "example": {
                "tool": "check_logo_presence",
                "check": "Check if health food logo is present"
            }
        }
```

## Rule Model

```python
class ParsedRule(BaseModel):
    rule_id: str = Field(
        ...,
        pattern=r"^R[a-f0-9]{6}_\d{2}$",
        description="Rule ID"
    )
    source: str = Field(..., min_length=1)
    description: str = Field(..., min_length=1)
    scene_tags: List[SceneTag] = Field(..., min_items=1)
    validation: ValidationConfig
```

## Custom Validators

```python
from pydantic import validator

class ParsedRule(BaseModel):
    # ... fields ...

    @validator('rule_id')
    def validate_rule_id(cls, v):
        if not re.match(r'^R[a-f0-9]{6}_\d{2}$', v):
            raise ValueError('Invalid rule ID format')
        return v

    @validator('scene_tags')
    def validate_scene_tags(cls, v):
        if not v:
            raise ValueError('Scene tags cannot be empty')
        return v

    @validator('validation')
    def validate_validation_config(cls, v):
        if v.tool not in AVAILABLE_TOOLS:
            raise ValueError(f'Unsupported tool: {v.tool}')
        return v
```

## Usage Examples

```python

    rule = ParsedRule(
        rule_id="R123456_01",
```

## Today's Reflection

Pydantic is essential for LLM output processing. LLMs produce "approximately correct" data - field names might be slightly wrong, types might be strings instead of numbers. Pydantic catches these issues immediately.

Key benefits I experienced:
1. **Early error detection**: Invalid data fails at parse time, not deep in business logic
2. **Clear error messages**: Pydantic tells you exactly what's wrong
3. **Documentation**: The schema doubles as API documentation
4. **Refactoring safety**: Change the model, get errors everywhere it breaks

One gotcha: Pydantic v1 and v2 have different APIs. We used v1 (`@validator`) but v2 (`@field_validator`) is now recommended.
