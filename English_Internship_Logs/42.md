# Rule Parser Design: From Complexity to Simplicity

> **Date**: 2024-01-19
> **Topic**: Evolving rule structures through iterative simplification

---

## Background

The rule parser converts regulatory text into structured rules for the compliance system. Today I reflected on how the rule structure evolved from complex to simple.

---

## Initial Complex Structure

The first version had many nested fields:

```json
{
  "rule_id": "R123456_01",
  "source": "Article X",
  "description": "Rule description",
  "priority": 1,
  "scene_tags": ["scene1", "scene2"],
  "requirements": [
    {
      "type": "text",
      "content": "Specific content",
      "visual_check_required": true,
      "check_type": "text",
      "tool": "text_recognition",
      "validation_criteria": "Validation standard"
    }
  ],
  "prohibitions": ["Prohibited content 1", "Prohibited content 2"],
  "risk_points": [
    {"description": "Risk", "severity": "high"}
  ],
  "tools_required": [
    {"tool": "tool_name", "purpose": "Usage", "parameters": {...}}
  ],
  "validation_steps": [
    {"step": 1, "action": "...", "tool": "...", "success_criteria": "..."}
  ]
}
```

---

## Problems with Complex Structure

1. **Redundancy**: Tool configuration repeated in multiple places
2. **Maintenance burden**: Hard to understand and update
3. **Performance**: Parsing overhead, storage waste
4. **LLM generation**: Harder to get consistent output

---

## Simplified Structure

After analysis, we reduced to essentials:

```json
{
  "rule_id": "R123456_01",
  "source": "Article X",
  "description": "Rule description",
  "scene_tags": ["YPGG", "QXGG", "BJGG"],
  "validation": {
    "tool": "image_text_recognition",
    "check": "Check advertisement content"
  }
}
```

## Implementation

```python
async def parse_raw_rule(self, raw_text: str, force_reparse: bool = False):
    # Generate hash for caching
    text_hash = hashlib.md5(raw_text.encode()).hexdigest()

    # Check cache
    if not force_reparse:
        cached = await self._check_cache(text_hash)
        if cached:
            return cached

    # Build prompt for LLM
    prompt = self._build_base_prompt(raw_text)

    # Call LLM
    response = await llm_chat(prompt)

    # Process and validate
    parsed = self._preprocess_parsed_data(response)

    # Cache result
    await self._save_parsed_result(parsed, text_hash)

    return parsed
```

| Parsing time | 150ms | 50ms | 67% faster |
| Storage | 2.5KB/rule | 0.8KB/rule | 68% smaller |

---

## Key Insights

1. **YAGNI applies**: Many fields were never used
2. **LLM consistency**: Simpler structures = more reliable generation
3. **Maintenance**: Less code = fewer bugs
4. **Onboarding**: New developers understand faster

---

## Today's Reflection

The evolution from complex to simple wasn't obvious from the start. We built the complex structure thinking we'd need flexibility. In practice, most fields went unused.

The lesson: **start simple, add complexity only when required**. It's easier to add fields than to remove them once code depends on them.

Another insight: LLMs generate simpler structures more reliably. When asking an LLM to produce JSON, complex nested structures lead to more parsing errors.
