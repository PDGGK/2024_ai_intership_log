## Background

The health food compliance system had accuracy issues: the OCR couldn't reliably identify visual elements like the "Blue Hat" certification mark, and the LLM wasn't following instructions consistently.

---

## Visual Recognition Issues

**Problem**: The VL model struggled with standardized visual elements.

The "Blue Hat" mark is a specific certification symbol that should appear on health food ads. But OCR-based detection missed it frequently because:
- Small size in images
- Low contrast against backgrounds
- Variable placement

**Solution approach**: Combine text extraction with dedicated visual element detection:

```python
class FeatureExtractor:
    def __init__(self, patterns: dict):
        self.patterns = patterns

    def extract(self, text: str) -> dict:
        results = {}
        for name, pattern in self.patterns.items():
            match = re.search(pattern, text)
            results[name] = {
                'found': bool(match),
                'content': match.group(0) if match else None
            }
        return results
```

## LLM Control Issues

**Problem**: The LLM ignored preprocessing results and produced inconsistent output.

**Solutions**:

1. **Structured prompts with mandatory sections**:
```python
PROMPT = f"""
System preprocessing results (MUST be reflected in output):
1. Non-pharmaceutical statement: {status}
   - Mandatory: {value}
2. Certification mark: {status}
   - Mandatory: {value}
"""
```

2. **Explicit format requirements**:
```python
"""
REQUIRED OUTPUT FORMAT:
{
    "is_or_not": boolean,
    "reason": "explanation",
    "reference": "regulatory basis"
}
"""
```

3. **Post-processing validation** to catch format violations.

## Today's Reflection

Visual recognition remains the weak link. Text extraction is reliable, but identifying specific visual elements (logos, certification marks) requires different techniques. Pure OCR isn't enough.

The LLM control issues were frustrating but solvable. The key was being **extremely explicit** about requirements. LLMs follow instructions better when you:
1. Number the requirements
2. Use all-caps for critical points
3. Include the exact output format
4. Add validation examples

I'm also more convinced that **preprocessing before LLM** is valuable. Instead of asking the LLM to find everything, do deterministic extraction first, then ask the LLM to interpret the results.
