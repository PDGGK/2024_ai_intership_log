## Background

The health food compliance system had validation logic conflicts - validators were overwriting each other's results, causing incorrect compliance judgments.

---

## The Validation Problem

Multiple validators were modifying `is_or_not` independently:

```python
@validator('is_or_not', always=True)
def validate_is_or_not(cls, v, values):
    # This might override a value set elsewhere
    if not v:
        return v
    # Check multiple conditions...
```

The LLM would set one value, then validators would override it based on partial information.

---

## Solution: Unified Validation Flow

```python
class HealthFoodAnalysisResult(BaseModel):
    is_or_not: bool
    reason: Optional[str]
    issues: List[ComplianceIssue] = []

    @validator('is_or_not', always=True)
    def validate_compliance_status(cls, v, values):
        # If issues exist, can't be compliant
        issues = values.get('issues', [])
        if issues and v is True:
            logger.warning("Inconsistent: marked compliant but issues exist")
            return False
        return v

    @validator('reason', always=True)
    def validate_reason(cls, v, values):
        is_compliant = values.get('is_or_not')
        issues = values.get('issues', [])

        if is_compliant:
            return "Advertisement complies with regulations"
        else:
            issue_desc = [f"{i+1}. {iss.description}" for i, iss in enumerate(issues)]
            return "Non-compliant: " + "; ".join(issue_desc)
```

## Multimodal Integration

Combining image recognition with text analysis:

```plaintext
Advertisement Image
    ├── VL Model → Visual Analysis (logos, layout)
    └── OCR → Text Extraction → LLM Analysis (claims, statements)
         ↓
    Combined Compliance Result
```

Both paths must agree for overall compliance.

## Today's Reflection

The validation conflicts taught me about Pydantic's execution order. Validators run in field definition order, and `always=True` means they run even if no value was provided. This can lead to surprising behavior when multiple validators touch the same state.

The solution was to make validators **derive values from source data**, not modify other fields. Each validator should be responsible for exactly one field.

Multimodal integration is powerful but complex. You need clear rules for how visual and textual evidence combine into a final judgment.
