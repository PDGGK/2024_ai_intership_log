## Background

Today I configured networking for my Ubuntu VM and set up a remote development workflow using SSH and VSCode. The goal was a seamless development experience from my Mac.

---

## VMware Network Modes

VMware provides three network modes:

| Mode | IP Range | External Access | Use Case |
|------|----------|-----------------|----------|
| **Bridged** (vmnet0) | Same as host network | Full | Production-like networking |
| **NAT** (vmnet8) | Private range | Via NAT | Default, good isolation |
| **Host-only** (vmnet1) | Private range | None | Secure isolated testing |

My configuration:
```plaintext
bridge100: 192.168.239.1/24  (Bridged)
bridge101: 192.168.110.1/24  (Host-only)
```

---

## SSH Remote Connection

Basic SSH setup:

```bash
# Connect to VM
ssh mu@192.168.110.130

# Verify network inside VM
ifconfig
```

For password-less login, copy SSH key:

```bash
ssh-copy-id mu@192.168.110.130
```

---

## VSCode Remote Development

The Remote-SSH extension enables full IDE features over SSH:

1. Install "Remote - SSH" extension
2. Add host to SSH config
3. Connect and open folder

This provides:
- Local editing of remote files
- Integrated terminal in VM
- Full IntelliSense and debugging

## Network Architecture

```plaintext
Mac Host
├── VMware Fusion
│   ├── bridge100 (192.168.239.1)
│   │   └── vmnet0 (bridged)
│   └── bridge101 (192.168.110.1)
│       ├── vmnet1 (host-only)
│       ├── vmnet2
│       └── vmnet3
└── Ubuntu VM (192.168.110.130)
    └── Connected via vmnet1
```

Host-only networking provides a stable IP for the VM without exposing it to the external network.

## Best Practices

**Environment Management**:
- Keep development environments reproducible
- Document setup steps for team collaboration

**Security**:
- Use host-only mode when external access isn't needed
- Configure firewall rules in VM
- Use SSH keys instead of passwords

---

## Today's Reflection

The remote development setup was worth the effort. VSCode over SSH feels nearly identical to local development, but the VM provides isolation and a consistent Linux environment.

One thing I learned: **host-only networking is underrated**. Bridged mode seems more natural, but it exposes the VM to the network and IP addresses can change with DHCP. Host-only provides a stable, private connection that's perfect for development.

The Python environment setup in the VM was straightforward. Ubuntu's package management is mature, and pip handles Python dependencies well. The VM now mirrors our production environment more closely than my Mac ever could.
