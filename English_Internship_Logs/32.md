## Background

## System Proxy vs TUN Mode

**System Proxy**:
- Works at application level
- Applications must respect proxy settings
- Simple to configure

**TUN Mode**:
- Creates virtual network interface
- Captures all traffic at OS level
- Works with any application

---

## System Proxy Configuration

```bash
# Environment variable method
export http_proxy=http://127.0.0.1:7897
export https_proxy=http://127.0.0.1:7897

# PAC script for selective proxying
function FindProxyForURL(url, host) {
    if (isInNet(host, "192.168.0.0", "255.255.0.0")) {
        return "DIRECT";
    }
    return "PROXY 127.0.0.1:7897";
}
```

System proxy is best for:
- Web browsers
- API calls and web services
- Package managers (pip, npm)

---

## TUN Mode Architecture

```plaintext
Application
    ↓
Operating System Network Stack
    ↓
TUN Virtual Network Card (Mihomo)
    ↓
Network Stack Processing
    ↓
Physical Network Card
```

TUN captures traffic before it leaves the OS, ensuring nothing bypasses the proxy.

---

## Network Stack Options

| Stack | Description | Use Case |
|-------|-------------|----------|
| System | Native kernel stack | Streaming, large files |
| GVisor | User-space implementation | Security-sensitive apps |
| Mixed | Dynamic selection | Complex environments |

## DNS Configuration

```plaintext
DNS hijacking in proxy environments:

User Request → TUN/Proxy Interception → Proxy DNS Processing
                                            ├→ Encrypted DNS (DOH/DOT)
                                            ├→ Custom DNS servers
                                            └→ DNS caching
```

The `any:53` configuration accepts DNS from all sources on port 53.

**Daily Use**:
- Web browsing → System Proxy

## Today's Reflection

Understanding proxy architecture helps debug network issues. When pip fails to download packages, is it the proxy? DNS? Firewall? Knowing the traffic path helps diagnose.

The key insight: **system proxy is opt-in, TUN is opt-out**. Applications can ignore system proxy settings, but TUN captures everything. For development, system proxy is usually sufficient and simpler. TUN is for when you need guaranteed coverage.

DNS hijacking was new to me. Proxies can intercept DNS to prevent leaks - your DNS queries go through the proxy too, not just HTTP traffic.
