## File Stream Management

**Problem**: Reading a file twice consumes the stream.

**Solution**: Create copies with BytesIO and reset pointers.

```python
from io import BytesIO

# Read content once
content = await file.read()

# Create a copy for each use
file_copy = UploadFile(
    filename=file.filename,
    file=BytesIO(content)
)

# Reset original pointer
file.file.seek(0)
```

## FastAPI Parameter Validation

422 errors usually mean parameter type mismatches. For file uploads:

```python
async def upload_handler(
    file: UploadFile = File(description="File to process"),
    param: str = Form(default="Default value")
)
```

Key points:
- Use `File()` for file parameters
- Use `Form()` for other multipart data
- Don't mix JSON body with file uploads

## Today's Reflection

File handling in async contexts is tricky. The concept of a "file stream" that gets consumed on read isn't intuitive if you're used to random-access files.

The key insight: **always create copies before passing files to multiple consumers**. BytesIO provides an in-memory file-like object that can be read multiple times by seeking back to the start.

The 422 errors were caused by mixing JSON and form data. FastAPI has strict rules about this - you can't use a Pydantic model for JSON body when you also have file uploads. Everything becomes Form data.
