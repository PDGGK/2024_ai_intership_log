## SSH 连接优化

### 免密登录

每次 SSH 都要输密码很烦，配置密钥认证：

```bash
# 在 Mac 上生成密钥对（如果还没有的话）
ssh-keygen -t ed25519

# 把公钥复制到虚拟机
ssh-copy-id mu@192.168.110.130
```

之后 SSH 连接就不用输密码了。

### SSH Config

在 `~/.ssh/config` 里配置别名：

```
Host ubuntu-vm
    HostName 192.168.110.130
    User mu
    IdentityFile ~/.ssh/id_ed25519
```

配置后直接 `ssh ubuntu-vm` 就能连接，不用记 IP 地址。

## 开发工具链

### Git 配置

```bash
git config --global user.name "Your Name"
git config --global user.email "your@email.com"
```

### Python 虚拟环境

项目用 venv 隔离依赖：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 常用开发依赖

```bash
# 编译相关
sudo apt install python3-dev build-essential

# 常用工具
sudo apt install git curl wget
```

## 环境隔离的理解

今天对环境隔离有了更深的理解：

```
层次结构：
├── 物理机 (Mac)
│   └── 虚拟机 (Ubuntu)  ← 操作系统级隔离
│       └── venv (.venv/)  ← Python 包隔离
│           └── 项目依赖
```

每一层都有隔离作用：
- 虚拟机隔离操作系统环境
- venv 隔离 Python 包版本

这样即使把环境搞坏了，也只影响当前层，不会波及其他项目。

## 今日反思

今天主要是一些配置优化，没什么大的技术挑战，但这些小配置累积起来能节省很多时间。

SSH 免密登录、config 别名这些，每次省几秒钟，但一天要连几十次，加起来就很可观了。之前总觉得这些配置是"锦上添花"，可做可不做，现在觉得应该一开始就配好。

另一个体会是：好的开发环境配置应该是"一次投入，长期收益"的。花半小时配好 SSH，之后每次连接都方便；花时间理解 venv，之后再也不用纠结依赖冲突。
