> **日期**: 2024-01-30

---

## 背景

规则解析系统需要确保数据的类型安全和有效性。今天整理了 Pydantic 在规则模型中的应用。

---

## 为什么选择 Pydantic

- **类型安全**：运行时类型检查，自动类型转换
- **数据验证**：复杂验证规则，自定义验证器
- **开发体验**：IDE 支持，自动文档生成

## 规则模型

```python
class ParsedRule(BaseModel):
    """解析后的规则模型"""
    rule_id: str = Field(
        ...,
        pattern=r"^R[a-f0-9]{6}_\d{2}$",
        description="规则ID"
    )
    source: str = Field(..., min_length=1, description="规则来源条款")
    description: str = Field(..., min_length=1, description="规则描述")
    scene_tags: List[SceneTag] = Field(
        ...,
        min_items=1,
        description="场景标签"
    )
    validation: ValidationConfig = Field(..., description="验证工具和方法")

    class Config:
        json_schema_extra = {
            "example": {
                "rule_id": "R123456_01",
                "source": "第X条",
                "description": "广告中必须包含保健食品标志",
                "scene_tags": ["BJGG"],
                "validation": {
                    "tool": "check_logo_presence",
                    "check": "检查是否包含标准的保健食品标志"
                }
            }
        }
```

## 使用示例

### 数据验证

```python
try:
    rule = ParsedRule(
        rule_id="R123456_01",
        source="第一条",
        description="示例规则",
        scene_tags=["YPGG"],
        validation={
            "tool": "image_text_recognition",
            "check": "检查广告内容"
        }
    )
    print("规则验证通过")

except ValidationError as e:
    print("规则验证失败:")
    print(e.json())
```

## 今日反思

今天整理 Pydantic 的用法，感觉这是 Python 类型系统的巨大进步。

以前写 Python，类型全靠文档和注释，运行时没有检查。参数传错了，可能跑到一半才报错。Pydantic 把类型检查提前到数据入口，不符合类型的数据根本进不来。

`Literal` 类型特别实用。工具名称只能是预定义的几个，用 `Literal["tool1", "tool2"]` 定义后，IDE 会自动补全，传错了立刻报错。

另一个收获是理解了"契约编程"的思想。Pydantic 模型就是数据契约——定义了数据应该是什么样的。上游保证传入符合契约的数据，下游放心使用，不用到处写防御性代码。

`json_schema_extra` 里的 example 也很有用。自动生成 API 文档时，这些示例会显示出来，方便使用者理解。
