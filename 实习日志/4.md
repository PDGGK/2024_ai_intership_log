## 今天的问题

今天在配置Docker环境时遇到一个选择题：Python依赖管理到底用Conda还是Pip？

之前一直用Pip，简单直接。但这个项目有一些科学计算的包（比如numpy、opencv），用Pip装经常遇到编译问题。于是开始认真研究两者的区别。

---

## Conda vs Pip：本质区别

查了一些资料，终于搞清楚了：

| 方面 | Pip | Conda |
|------|-----|-------|
| 定位 | 纯粹的包管理工具 | 环境管理 + 包管理 |
| 包来源 | PyPI | Anaconda仓库 + conda-forge |
| 依赖解析 | 相对简单 | 更复杂，会考虑非Python依赖 |
| 二进制包 | 部分有wheel | 大多数都有预编译版本 |

**我的结论**：如果项目用到科学计算包，Conda更省心；如果是纯Web项目，Pip足够了。

这个项目涉及图像处理和机器学习，最终决定用Conda。

## Docker配置优化

### 基础Dockerfile

```dockerfile
FROM python:3.9-slim

WORKDIR /app

# 配置apt源为国内镜像
RUN echo \
    "deb https://mirrors.tuna.tsinghua.edu.cn/debian/ bullseye main contrib non-free" \
    > /etc/apt/sources.list

# 安装系统依赖
RUN apt-get update && apt-get install -y \
    git \
    poppler-utils \
    libgl1-mesa-glx \
    libglib2.0-0 \
    && rm -rf /var/lib/apt/lists/*
```

这里 `poppler-utils` 是PDF处理需要的，`libgl1-mesa-glx` 和 `libglib2.0-0` 是OpenCV需要的。一开始漏了这些，运行时报错才发现。

### 网络配置

国内环境下，Docker的网络配置很关键：

```json
{
  "registry-mirrors": [
    "https://hub-mirror.c.163.com",
    "https://mirror.baidubce.com",
    "https://registry.docker-cn.com"
  ],
  "dns": ["8.8.8.8", "8.8.4.4"],
  "max-concurrent-downloads": 3,
  "max-concurrent-uploads": 3,
  "mtu": 1400
}
```

几个要点：
- 配置多个镜像源，一个挂了还有备选
- DNS用Google的，避免解析问题
- `mtu` 设置为1400可以避免一些网络问题

### requirements.txt 管理

```txt
fastapi>=0.68.0
uvicorn>=0.15.0
python-multipart>=0.0.5
pillow>=8.3.1
pdf2image>=1.16.0
python-magic>=0.4.24
loguru>=0.5.3
pydantic<2.0.0  # 锁定版本，2.0有破坏性变更
```

版本管理的经验：
- 用 `>=` 允许小版本更新
- 用 `<` 避免大版本破坏性变更
- 重要依赖记得写注释说明为什么锁定

## 包管理演进历史

今天顺便了解了一下Python包管理的历史，挺有意思的：

```
distutils (早期，简单分发)
    ↓
setuptools (更多功能)
    ↓
pip (成为标准)
    ↓
virtualenv (环境隔离)
    ↓
conda (环境+包一体化)
    ↓
poetry (现代化依赖管理)
```

现在还有Poetry这个新工具，据说解决了很多pip的痛点，有空可以研究一下。

## 技术选型的思考

今天做选型时总结了一个评估框架：

1. **技术成熟度** - 有多少人在用？遇到问题能不能搜到解决方案？
2. **社区活跃度** - 还在积极维护吗？issue响应快吗？
3. **学习曲线** - 团队能多快上手？
4. **维护成本** - 长期用下来会不会有坑？
5. **生态系统** - 和现有工具链能不能配合？

没有最好的技术，只有最适合的技术。

---

## 今日反思

今天最大的收获是理解了"选型"这件事。

以前总觉得技术选型就是选"最好"的，但其实不是。好的选型要考虑团队现状、项目需求、长期维护等多个因素。比如这次选Conda，不是因为Conda"比Pip好"，而是因为它更适合这个项目的需求。

另外一个体会是：**遇到问题先查官方文档**。今天研究Conda vs Pip的时候，看了很多博客文章，说法不一。最后还是官方文档最准确。
