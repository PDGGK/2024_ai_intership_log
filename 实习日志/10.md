## 遇到的问题

### 问题一：虚拟环境路径混乱

`pip install` 的包没装到虚拟环境里，装到了系统 Python 里。排查发现是虚拟环境没激活成功。

解决方案：重建虚拟环境。

```bash
# 退出当前环境
deactivate

# 删除旧环境
rm -rf .venv

# 重新创建
python3 -m venv .venv

# 激活
source .venv/bin/activate

# 验证
which python  # 应该是 .venv/bin/python
which pip     # 应该是 .venv/bin/pip
```

### 问题二：SSL 证书验证失败

公司网络环境的老问题，pip 装包时 SSL 验证失败。

```bash
pip install -r requirements_mac.txt \
    --trusted-host pypi.org \
    --trusted-host files.pythonhosted.org \
    -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 问题三：系统依赖缺失

运行时报错找不到 `poppler`，这是 PDF 处理需要的系统库。

```bash
brew install poppler
```

装完后还需要确保 Python 能找到它：

```bash
export PATH="/opt/homebrew/bin:$PATH"
```

## FastAPI 服务启动

依赖装好后，启动服务：

```bash
uvicorn main:app --host 0.0.0.0 --port 9001 --reload
```

几个参数说明：
- `--host 0.0.0.0`：允许外部访问
- `--port 9001`：指定端口
- `--reload`：开发模式，代码修改自动重载

服务起来后，访问 `http://localhost:9001/docs` 可以看到 Swagger 文档界面，很方便测试 API。

## FastAPI 技术栈

今天顺便研究了一下 FastAPI 的架构：

```
FastAPI (Web框架)
    ↓
Starlette (ASGI框架)
    ↓
Uvicorn (ASGI服务器)
```

FastAPI 的核心优势：
- **类型提示**：用 Python 的 type hints 定义参数，自动生成文档
- **异步支持**：原生 async/await，处理并发请求性能好
- **Pydantic**：强大的数据验证，自动校验请求参数
- **OpenAPI**：自动生成 API 文档和交互界面

对比其他框架：

| 框架 | 特点 |
|------|------|
| Flask | 简单灵活，但功能较少 |
| Django | 功能全面，但较重 |
| FastAPI | 现代化，性能好，文档自动生成 |

## 今日反思

今天最大的教训是：**环境问题一定要彻底解决**。

一开始虚拟环境没激活成功，装的包跑到系统 Python 里了，排查了好久才发现。以后每次激活环境后，第一件事就是用 `which python` 确认一下。

另一个体会是：FastAPI 确实很适合写 API 服务。类型提示不仅能自动生成文档，IDE 的代码补全也更智能。写惯了之后很难回到 Flask 那种手动写文档的方式。

今天算是把本地开发环境彻底搭好了，后面可以专心调试业务逻辑了。
