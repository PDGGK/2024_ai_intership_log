> **日期**: 2024-12-01
> **主题**: 跨平台依赖处理与系统工具安装

---

## 今天的任务

在 Ubuntu 虚拟机上部署 OCR 项目，遇到了几个跨平台问题。

---

## 问题一：Windows 专用包

安装依赖时报错：

```bash
ERROR: Could not find a version that satisfies the requirement pywin32==308
ERROR: No matching distribution found for pywin32==308
```

`pywin32` 是 Windows 专用的包，Linux 上装不了。

解决方案：过滤掉 Windows 专用包

```bash
# 手动过滤
grep -v "pywin32" requirements.txt > requirements_linux.txt
pip install -r requirements_linux.txt
```

更好的方式是在 requirements.txt 里用环境标记：

```
pywin32==308; sys_platform == 'win32'
```

这样 pip 会自动根据平台跳过不兼容的包。

---

## 问题二：PDF 处理失败

运行时报错：

```
Unable to get page count. Is poppler installed and in PATH?
```

原因是缺少 `poppler-utils`，这是 PDF 渲染需要的系统级工具。

```bash
sudo apt-get update
sudo apt-get install -y poppler-utils
```

## 系统架构理解

今天对系统的层次结构有了更清晰的认识：

```
Ubuntu 虚拟机
├── 系统工具 (poppler-utils, build-essential...)
│   └── 这些是操作系统级别的依赖
│
├── Python 环境
│   ├── 系统 Python (/usr/bin/python3)
│   └── 虚拟环境 (.venv/)
│       └── 项目依赖 (pip 安装的包)
│
└── 应用代码
    └── 业务逻辑
```

之前一直把 pip 包和系统工具混淆，今天终于理清了：
- **pip 安装**：Python 包，只能在 Python 代码里 import
- **apt 安装**：系统工具，是独立的可执行程序

有些 Python 包（比如 pdf2image）依赖系统工具（poppler），pip 能装 Python 包，但系统工具得用 apt 装。

## 网络地址概念

顺便理清了几个 IP 地址的区别：

| 地址 | 含义 | 使用场景 |
|------|------|----------|
| `0.0.0.0` | 监听所有网络接口 | 服务端绑定地址 |
| `127.0.0.1` | 本地回环 | 只允许本机访问 |
| `192.168.x.x` | 局域网地址 | 局域网内访问 |

服务启动时绑定 `0.0.0.0:9001`，意味着从任何网络接口都能访问。如果绑定 `127.0.0.1:9001`，就只能在本机访问。

## 今日反思

今天遇到的问题都是跨平台开发的典型问题。

最大的教训是：**Windows 和 Linux 的差异比想象中大**。不只是命令行不一样，很多包、系统工具、路径格式都不同。以后写代码要多考虑跨平台兼容性，requirements.txt 里也要用环境标记来区分平台特定的依赖。

另一个收获是理解了 pip 包和系统工具的区别。之前遇到 "找不到 xxx" 的错误就只会 pip install，现在知道要先判断是 Python 包还是系统工具。
