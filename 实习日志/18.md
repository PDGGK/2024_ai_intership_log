## 问题一：API 404 错误

服务启动了，但从 Mac 访问返回 404。

排查过程：
1. 检查服务是否真的在跑 → `curl localhost:9001` 正常
2. 检查监听地址 → 发现绑定的是 `127.0.0.1`

问题就在这。`127.0.0.1` 是本地回环地址，只能在虚拟机内部访问。要让外部访问，得绑定 `0.0.0.0`。

```python
def run_api_server():
    host = "0.0.0.0"  # 监听所有接口，外部可访问
    port = 9001
    uvicorn.run(app, host=host, port=port)
```

改完后从 Mac 就能正常访问了。

## 问题二：Git 合并冲突

拉代码时提示冲突：

```bash
git pull origin main
# CONFLICT (content): Merge conflict in xxx.py
```

之前没怎么处理过冲突，今天学了一下标准流程：

```bash
# 1. 查看哪些文件冲突
git status

# 2. 打开冲突文件，手动解决
vim <filename>
# 冲突标记长这样：
# <<<<<<< HEAD
# 本地代码
# =======
# 远程代码
# >>>>>>> origin/main

# 3. 删除冲突标记，保留正确的代码

# 4. 提交解决结果
git add <files>
git commit -m "resolve merge conflicts"
```

另外，在虚拟机上第一次 commit 时提示要配置用户信息：

```bash
git config --global user.email "your@email.com"
git config --global user.name "Your Name"
```

## 开发环境对比

今天在虚拟机里用 vim 写代码，和在 Mac 上用 VSCode 体验差距挺大的。

| 方面 | 虚拟机 + vim | Mac + VSCode |
|------|-------------|--------------|
| 隔离级别 | 系统级隔离 | Python 包级隔离 |
| 开发体验 | 纯命令行 | 图形界面、代码补全 |
| 资源占用 | 独立资源 | 共享系统资源 |
| 调试 | 打印日志 | 断点调试 |

结论：虚拟机适合部署和测试，日常开发还是用 VSCode Remote-SSH 更方便。

## 今日反思

今天踩的两个坑都不难，但排查时走了弯路。

404 错误一开始以为是路由没注册对，检查了半天路由代码。后来才想到可能是网络问题，一看监听地址就找到原因了。以后遇到问题要**从外向内排查**：先确认网络通不通，再看服务配置，最后看代码逻辑。

Git 冲突以前都是逃避的——直接删了本地改动重新 clone。今天硬着头皮学了一下，发现也没那么难。冲突标记很清楚，看懂就知道怎么解决了。
