### 问题二：JSON 解析错误

LLM 返回的结果解析失败，报 JSON 格式错误。

原因是 LLM 返回的内容里除了 JSON 还有额外的解释文字。解决方案是用正则提取 JSON 部分：

```python
def extract_json(text: str) -> dict:
    # 匹配 {...} 或 [...]
    pattern = r'[\{\[].*[\}\]]'
    match = re.search(pattern, text, re.DOTALL)
    if match:
        return json.loads(match.group())
    raise ValueError("No JSON found in text")
```

## 代码优化

之前的代码有几个问题：
1. JSON 处理逻辑过于复杂
2. 数据模型转换冗余
3. 错误处理层级太多

优化后：
- 简化 JSON 提取逻辑
- 统一用 `BaseJudgementResponse` 包装返回
- 错误处理只保留必要的一层

---

## batch_size 参数

这个参数控制批处理大小。

| batch_size | 效果 |
|------------|------|
| 1 | 一页一页处理，稳定但慢 |
| 较大值 | 多页并行处理，快但占用更多显存 |

对于处方药广告这种场景，广告通常就一两页，batch_size=1 足够了。

## 今日反思

今天完成了第一个实际场景的开发，从开始到部署测试通过，收获很大。

最大的体会是：**先让代码跑起来，再考虑优化**。一开始我想把代码写得很"漂亮"，各种抽象封装，结果反而增加了复杂度。后来简化成最直接的实现，代码量少了一半，反而更清晰。

另一个教训是：LLM 的输出不能完全信任。它可能返回格式不正确的内容，也可能返回额外的解释文字。所以一定要有容错处理。
