## 遇到的问题

### 问题一：文件流重用

同一个文件需要在两个地方使用：
1. VL 模型识别文字
2. 图像对比检测 Logo

第一次读取后，文件指针到了末尾，第二次读取就是空的。

### 解决方案

```python
# 方案一：重置文件指针
content = await file.read()
file.file.seek(0)  # 重置到开头

# 方案二：复制文件内容
from io import BytesIO

content = await file.read()
file_copy = UploadFile(
    filename=file.filename,
    file=BytesIO(content)
)
```

我用的是方案二，创建一个副本给图像对比功能用。

---

### 问题二：422 参数验证错误

FastAPI 返回 422 错误，说参数格式不对。

原因是混用了 `File()` 和 `Form()`，但请求的 Content-Type 不是 multipart/form-data。

```python
# 正确的参数声明
async def upload_handler(
    file: UploadFile = File(description="文件"),
    param: str = Form(default="默认值")  # Form 参数需要默认值
)
```

用 Apifox 测试时，要选择 "form-data" 格式发送请求。

## BytesIO 使用总结

| 场景 | 做法 |
|------|------|
| 读取文件内容 | `content = await file.read()` |
| 重置读取位置 | `file.file.seek(0)` |
| 创建内存文件 | `BytesIO(content)` |
| 复制 UploadFile | `UploadFile(filename=..., file=BytesIO(content))` |

## 今日反思

今天主要是处理文件流的问题。

之前没注意过文件指针这个概念，以为 `read()` 可以反复调用。实际上文件是流式读取的，读完后指针在末尾，再读就是空的。这个问题不只是 FastAPI，所有文件操作都一样。

另一个收获是：**集成比开发更麻烦**。昨天单独开发图像对比功能很顺利，今天集成进来就遇到各种问题——文件流重用、参数验证、结果合并。以后开发新功能时，要提前考虑集成场景。
