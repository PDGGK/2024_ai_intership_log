## 依赖分层管理

把依赖文件拆分成多个层级：

```
requirements/
├── base.txt        # 基础依赖，所有环境都需要
├── production.txt  # 生产环境额外依赖
└── development.txt # 开发环境额外依赖
```

**base.txt**：
```txt
fastapi>=0.68.0
uvicorn>=0.15.0
pydantic>=1.8.0
```

**development.txt**：
```txt
-r base.txt
pytest>=6.0.0
black>=21.0
mypy>=0.9
```

**production.txt**：
```txt
-r base.txt
gunicorn>=20.0.0
```

这样开发环境可以装测试工具，生产环境保持精简。

## 多阶段构建优化

```dockerfile
# 构建阶段：安装依赖
FROM python:3.10 AS builder
WORKDIR /build
COPY requirements.txt .
RUN pip wheel --no-cache-dir --no-deps -r requirements.txt -w /wheels

# 运行阶段：只复制必要的文件
FROM python:3.10-slim
COPY --from=builder /wheels /wheels
RUN pip install --no-cache /wheels/*
WORKDIR /app
COPY . .
CMD ["uvicorn", "main:app", "--host", "0.0.0.0"]
```

用 `pip wheel` 先把依赖打包成 wheel 文件，然后在运行阶段直接安装。这样：
- 构建阶段的编译工具不会进入最终镜像
- wheel 文件安装比从源码安装快很多

## 容器技术发展简史

今天顺便了解了一下容器技术的发展历程：

| 年份 | 事件 |
|------|------|
| 2013 | Docker 首次发布 |
| 2015 | Docker Compose 推出 |
| 2017 | Moby Project 启动，Docker 开源核心 |
| 2020 | Docker Desktop for Apple Silicon |
| 2022 | Docker 收费策略调整 |

现在的容器技术栈：
- **容器运行时**：Docker, containerd, CRI-O
- **编排平台**：Kubernetes, Docker Swarm
- **镜像仓库**：Docker Hub, Harbor, 阿里云容器镜像服务

## 生产环境注意事项

### 安全性
- 不要用 root 用户运行应用
- 及时更新基础镜像，修复安全漏洞
- 敏感信息用环境变量或 secrets 管理，不要写在 Dockerfile 里

### 性能
- 选择合适的基础镜像（slim vs alpine vs 完整版）
- 合理设置资源限制（CPU、内存）
- 启动时间优化

### 可观测性
- 日志输出到 stdout/stderr
- 添加健康检查接口
- 暴露 metrics 接口

## 常见问题排查

| 问题 | 可能原因 | 排查方法 |
|------|----------|----------|
| 构建失败 | 依赖冲突或网络问题 | 查看构建日志，检查 requirements.txt |
| 启动失败 | 配置错误或端口冲突 | `docker logs` 查看日志 |
| 运行异常 | 环境变量缺失 | `docker exec` 进入容器检查 |
| 性能问题 | 资源不足或镜像过大 | `docker stats` 查看资源使用 |
