## 今天遇到的问题

运行代码时报错：

```python
from vl.utils import check_file_size
# ModuleNotFoundError: No module named 'vl'
```

---

## 问题分析

Python 找不到 `vl` 模块，原因可能是：
1. 模块确实不存在
2. Python 路径配置不对
3. 包结构不正确

经排查是第二个原因：PYTHONPATH 没有包含项目根目录。

---

## 解决方案

### 方案一：命令行设置

```bash
export PYTHONPATH="${PYTHONPATH}:$(pwd)"
python main.py
```

### 方案二：VSCode launch.json 配置

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Python: FastAPI",
            "type": "python",
            "request": "launch",
            "module": "uvicorn",
            "args": ["startup:app", "--reload"],
            "cwd": "${workspaceFolder}",
            "env": {
                "PYTHONPATH": "${workspaceFolder}"
            }
        }
    ]
}
```

关键是 `env` 里设置 `PYTHONPATH`。

## Python 导入机制

### 绝对导入 vs 相对导入

```python
# 绝对导入：从项目根目录开始
from vl.utils import check_file_size

# 相对导入：从当前模块位置开始
from .utils import check_file_size  # 当前包的 utils
from ..common import helper         # 上级包的 common
```

相对导入只能在包内部使用，不能在顶层脚本里用。

### 包的结构

一个合法的 Python 包需要 `__init__.py`：

```
project/
├── vl/
│   ├── __init__.py
│   └── utils.py
├── main.py
└── startup.py
```

## VSCode 调试技巧

### 断点

- 点击行号左边设置断点（红点）
- 条件断点：右键 → 添加条件断点
- 日志断点：不暂停，只打印日志

### 调试控制台

程序在断点暂停时，可以在调试控制台执行 Python 代码：

```python
# 查看变量
print(doc_result)

# 格式化输出 JSON
import json
print(json.dumps(obj, indent=2, ensure_ascii=False))

# 测试表达式
len(pages)
```

### 变量监视

在"监视"面板添加表达式，实时查看值的变化。

## 调试 FastAPI

FastAPI 的调试比普通 Python 脚本复杂一点，因为它是通过 uvicorn 启动的。

launch.json 配置要点：
- `module` 设为 `uvicorn`
- `args` 里指定入口文件和选项
- 设置 `PYTHONPATH` 确保导入正确

调试流程：
1. 启动调试（F5）
2. 用 Apifox 或 curl 发请求
3. 程序会在断点暂停
4. 在调试控制台检查变量

## OCR 优化发现

调试过程中发现一个问题：给 VL 模型传的 prompt 参数太复杂，反而影响识别效果。

```python
# 之前：复杂的提示词
vl_prompt = "请识别图片中的文字，特别注意蓝帽子标志、声明文字..."

# 之后：简单或不传
vl_prompt = None  # 使用默认配置
```

移除多余的 prompt 后，识别效果反而更好了。

## 数据处理代码

调试时发现的一个有用模式：

```python
text_content = "\n".join(
    [page["content"] for page in doc_result["pages"] if page["status"] == "success"]
).strip()
```

只处理成功的页面，跳过失败的页面，然后去除首尾空白。
