## 遇到的问题

### 问题一：ISO 启动失败

创建虚拟机后，从 ISO 启动直接黑屏，进不了安装界面。

排查过程：
1. 检查 ISO 完整性（校验 SHA256）→ 正常
2. 检查虚拟机设置 → 发现问题

原因是 ISO 挂载到了 SATA 设备，但 ARM 虚拟机应该用 NVMe。

解决方案：
- 删除 SATA CD/DVD 设备
- 添加 NVMe CD/DVD 设备
- 重新挂载 ISO

### 问题二：UEFI 启动配置

即使 ISO 挂载正确，还是启动失败。进入 UEFI 设置发现启动顺序不对。

解决方案：
1. 开机时按 `F2` 进入 UEFI 设置
2. 调整 Boot Order，把 CD/DVD 放在第一位
3. 保存退出

### 问题三：安装后无法启动

Ubuntu 安装完成后，重启卡在黑屏。

原因：安装后 CD/DVD 还在启动顺序的第一位，系统在尝试从空的 CD/DVD 启动。

解决方案：
- 移除 CD/DVD 设备，或
- 调整启动顺序，硬盘优先

## UEFI 启动流程

今天顺便学习了 UEFI 启动的原理：

```
1. 固件初始化
   ↓
2. 加载 UEFI 引导程序
   ↓
3. 识别启动设备（根据 Boot Order）
   ↓
4. 加载 Bootloader（如 GRUB）
   ↓
5. 加载操作系统内核
```

传统 BIOS 和 UEFI 的区别：

| 方面 | BIOS | UEFI |
|------|------|------|
| 界面 | 文本 | 图形化 |
| 启动方式 | MBR | GPT |
| 安全启动 | 不支持 | 支持 |
| 启动速度 | 较慢 | 较快 |

现代系统基本都用 UEFI 了，VMware Fusion 的 ARM 虚拟机也是 UEFI。

## 虚拟机管理操作

一些常用操作：

### 状态管理
```
菜单：Virtual Machine → Power
- Shut Down：正常关机（发送关机信号给系统）
- Power Off：强制关机（相当于拔电源）
- Restart：重启
- Suspend：挂起（保存状态到磁盘）
```

### 快照管理
```
菜单：Virtual Machine → Snapshots
- Take Snapshot：创建快照
- Revert to Snapshot：恢复到快照
```

快照很有用，在做危险操作前先拍个快照，出问题可以回滚。

### 快捷键
```
Control + Command + F：全屏/退出全屏
Control + Command + G：释放鼠标（当鼠标被虚拟机捕获时）
Control + Alt：同上（Linux 习惯）
```

## 虚拟机文件位置

虚拟机文件存储在：
```
~/Virtual Machines.localized/虚拟机名称.vmwarevm/
```

里面包含：
- `.vmx`：虚拟机配置文件
- `.vmdk`：虚拟磁盘文件
- `.nvram`：UEFI 设置
- `.vmss`：挂起状态文件

删除虚拟机时，记得把这个目录也删掉，不然会占用磁盘空间。

## 今日反思

今天遇到的问题都是一些"小坑"，但排查起来花了不少时间。

最大的教训是：**出问题时要系统排查，不要瞎猜**。一开始 ISO 启动失败，我以为是 ISO 损坏了，重新下载了一遍，结果问题根本不在那里。后来一步步检查虚拟机设置，才发现是存储设备类型的问题。

另一个体会是：**理解启动流程很重要**。知道 UEFI 的启动顺序是怎么工作的，就能快速定位"安装后无法启动"的问题。很多看似神秘的问题，理解原理后就很简单。
