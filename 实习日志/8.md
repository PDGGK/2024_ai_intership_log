## 问题一：虚拟环境管理

VSCode 里显示有好几个虚拟环境可选，有点混乱。最后决定统一用项目目录下的 `.venv`。

创建和激活流程：

```bash
# 创建虚拟环境
python3 -m venv .venv

# 激活环境（Mac/Linux）
source .venv/bin/activate

# 激活环境（Windows）
.venv\Scripts\activate.bat

# 确认当前环境
which python  # 应该指向 .venv/bin/python
```

在 VSCode 中：
1. `Cmd+Shift+P` 打开命令面板
2. 搜索 "Python: Select Interpreter"
3. 选择 `.venv` 下的解释器

## 问题二：Windows 专用包

从 Windows 同事那里拿来的项目，requirements.txt 里有 `pywin32`。在 Mac 上装不了。

解决方案是创建平台特定的依赖文件：

```bash
# 从原文件生成 Mac 版本
grep -v "pywin32" requirements.txt > requirements_mac.txt

# 安装
pip install -r requirements_mac.txt
```

更优雅的方案是用条件依赖：

```txt
# requirements.txt
pywin32==308; platform_system=="Windows"
```

这样在非 Windows 平台会自动跳过。

## 问题三：SSL 证书验证失败

`pip install` 时报 SSL 证书错误，应该是公司网络的问题。

临时解决方案：

```bash
pip install -r requirements.txt \
    -i https://pypi.tuna.tsinghua.edu.cn/simple \
    --trusted-host pypi.tuna.tsinghua.edu.cn
```

永久配置：

```bash
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
pip config set global.trusted-host pypi.tuna.tsinghua.edu.cn
```

## 虚拟环境原理

虚拟环境本质上是在项目目录下创建了一个独立的 Python 环境，包括：
- Python 解释器的符号链接
- 独立的 `site-packages` 目录
- 激活脚本

激活脚本做的事情很简单，主要是修改 `PATH` 环境变量：

```python
# 激活脚本核心逻辑（简化版）
import os
base = os.path.dirname(os.path.dirname(__file__))
os.environ["VIRTUAL_ENV"] = base
os.environ["PATH"] = os.path.join(base, "bin") + ":" + os.environ["PATH"]
```

这样 `python` 和 `pip` 命令就会指向虚拟环境里的版本。

## 依赖管理最佳实践

### requirements.txt 写法

```txt
# 精确版本（推荐用于生产）
fastapi==0.68.1

# 最小版本
uvicorn>=0.15.0

# 版本范围
pydantic>=1.8.0,<2.0.0

# 兼容版本（~= 等价于 >=1.8.0,<1.9.0）
requests~=2.26.0
```

### 依赖锁定

```bash
# 生成当前环境的精确依赖
pip freeze > requirements.lock

# 开发时用 requirements.txt，部署时用 requirements.lock
```

### 分层依赖

```txt
# requirements-dev.txt
-r requirements.txt
pytest>=6.0.0
black>=21.0
```

## 今日反思

今天学到的最重要的一点是：**开发环境配置是值得投入时间的**。

以前总觉得配置环境是浪费时间，能跑就行。但今天发现，环境配置得好，后续开发会顺畅很多。比如虚拟环境配置好了，就不会污染系统 Python；依赖管理做好了，团队协作就不会出现"在我电脑上能跑"的问题。

另一个体会是：**遇到问题要系统排查**。SSL 证书问题一开始没想到是网络的锅，花了不少时间。以后遇到问题，要从环境、依赖、网络、权限这几个方面系统检查。
