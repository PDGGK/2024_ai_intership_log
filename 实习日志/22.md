## 模型重构

### 之前的问题

原来的模型继承比较乱：
- 有的继承 `BaseResponse`
- 有的继承 `BaseModel`
- 没有统一的基类

### 重构后的结构

统一用 `BaseJudgement` 作为业务模型的基类：

```python
class BaseJudgement(BaseModel):
    is_or_not: bool    # 是否违规
    reason: str        # 判断理由
    reference: str     # 法规依据
```

场景模型继承它：

```python
class HealthFoodAnalysisResult(BaseJudgement):
    disease_check: DiseaseFunctionCheck
    declaration_check: MedicineDeclarationCheck
    identification_check: IdentificationCheck
```

这样所有业务模型都有统一的基础字段，代码复用性更好。

## Pydantic 深入学习

### 字段定义

```python
# 必填字段
name: str = Field(..., description="名称")

# 可选字段，默认 None
description: Optional[str] = Field(None, description="描述")

# 带约束的字段
age: int = Field(..., gt=0, lt=150, description="年龄")
email: str = Field(..., regex=r'^[\w\.-]+@[\w\.-]+\.\w+$')
```

### 验证器

```python
class User(BaseModel):
    name: str
    age: int

    @validator('age')
    def validate_age(cls, v):
        if v < 0:
            raise ValueError('年龄不能为负')
        return v

    @validator('name')
    def validate_name(cls, v, values):
        # values 包含之前已验证的字段
        if len(v) < 2:
            raise ValueError('名称至少2个字符')
        return v.strip()
```

验证器按字段定义顺序执行，可以通过 `values` 访问之前的字段。

## 技术栈关系

```
FastAPI
├── Starlette (底层 ASGI 框架)
├── Pydantic (数据验证)
│   ├── BaseModel (基础模型)
│   ├── Field (字段定义)
│   └── validator (验证器)
└── Python Type Hints (类型注解)
```

FastAPI 之所以能自动验证请求参数、生成 API 文档，核心就是 Pydantic。理解 Pydantic 是理解 FastAPI 的关键。

## 今日反思

今天主要做模型重构，代码改动不大，但思考得比较多。

一开始我纠结用继承还是组合。继承的好处是子类自动有父类的字段，但层级太深会变复杂；组合更灵活，但要手动处理共有字段。最后决定：**业务相关的用继承，技术相关的用组合**。`BaseJudgement` 是业务概念，所有判断结果都有"是否违规"、"理由"、"依据"这些字段，用继承合适。

另一个收获是深入学习了 Pydantic。之前只会简单用，今天仔细看了 Field 和 validator 的用法。Pydantic 的验证能力很强，善用它可以省掉很多手写的校验代码。
