# 虚拟化技术与系统架构选择

> **日期**: 2024-11-27
> **主题**: VMware Fusion 与 Ubuntu 虚拟机配置

---

## 背景

项目需要一个 Linux 开发环境。Mac 上有几种选择：
1. Docker（容器化）
2. VMware Fusion（虚拟机）
3. Parallels Desktop（虚拟机）
4. UTM（虚拟机，开源）

考虑到需要完整的 Linux 桌面环境来调试一些 GUI 相关的功能，最终选择了 VMware Fusion。

---

## VMware Fusion 版本选择

VMware Fusion 有两个版本：

| 版本 | 特点 | 价格 |
|------|------|------|
| Player | 基础虚拟化功能，个人免费 | 免费 |
| Pro | 高级网络、加密、快照等功能 | 付费 |

个人开发用 Player 版本足够了。从 VMware 官网下载，注册账号后可以获得免费许可证。

---

## ARM 架构的考虑

M 系列芯片是 ARM64 架构，这意味着：

| 架构 | 优势 | 劣势 |
|------|------|------|
| ARM64 原生 | 性能好，能耗低 | 软件生态相对较少 |
| x86 模拟 | 软件兼容性好 | 性能损耗大，约 50% |

结论：尽量用 ARM 版本的 Linux。Ubuntu 有官方的 ARM64 版本，兼容性和稳定性都不错。

---

## Ubuntu 版本选择

选择 Ubuntu 22.04 LTS（ARM64）：
- LTS 版本支持周期长（5年）
- 软件包较新
- 社区支持好

下载地址：Ubuntu 官网的 ARM64 Server/Desktop ISO。

## 虚拟机配置

创建虚拟机时的配置建议：

```
CPU: 4核（根据物理机配置调整）
内存: 8GB（最少4GB）
磁盘: 64GB（动态分配）
网络: NAT（开发环境够用）
```

UEFI 设置注意事项：
- 确保 Secure Boot 关闭（某些 Linux 版本有问题）
- 启动顺序设置 ISO 优先

## 虚拟化技术原理

今天顺便了解了一下虚拟化的原理：

```
物理硬件
    ↓
Hypervisor（VMware Fusion）
    ↓
虚拟硬件（虚拟CPU、虚拟内存、虚拟磁盘）
    ↓
客户操作系统（Ubuntu）
```

VMware Fusion 属于 Type 2 Hypervisor（运行在操作系统之上），和 Type 1（直接运行在硬件上，如 ESXi）不同。

对于 M 系列 Mac：
- VMware Fusion 使用 Apple 的 Hypervisor.framework
- 不需要 Rosetta 模拟，ARM 虚拟机性能接近原生
- x86 虚拟机需要模拟，性能较差

今天主要是调研和选型，没有太多实际操作。但我觉得这个过程很有价值。
