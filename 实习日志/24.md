# OCR 识别优化与 LLM 输出控制

> **日期**: 2024-12-12
> **主题**: 视觉识别准确性提升与提示词工程

---

## 今天遇到的问题

保健食品广告审查系统有两个问题：
1. OCR 识别不准确，特别是蓝帽子标志这种视觉元素
2. LLM 输出不稳定，格式不统一

---

## 问题一：视觉识别

### 问题描述

OCR 系统识别"蓝帽子"标志的结果很不稳定：
- 有时候能识别出来
- 有时候完全识别不到
- 有时候识别错误

### 分析

蓝帽子是一个图形标志，不是文字。VL 模型虽然能处理图像，但对这种标准化的视觉符号识别效果不稳定。

### 解决思路

考虑两种方案：

1. **预处理检测**：用专门的图像检测模型先检测是否有蓝帽子，把结果告诉 LLM
2. **多模态融合**：让 VL 模型同时输出图像描述和文字识别结果

目前采用方案一，更可控：

```python
class FeatureExtractor:
    def __init__(self, patterns: dict):
        self.patterns = patterns

    def extract(self, text: str) -> dict:
        results = {}
        for feature_name, pattern in self.patterns.items():
            match = re.search(pattern, text)
            results[feature_name] = {
                'found': bool(match),
                'content': match.group(0) if match else None
            }
        return results
```

## 问题二：LLM 输出控制

### 问题描述

LLM 返回的结果有时候：
- 中英文混杂
- 格式不统一
- 没有严格按照预处理结果输出

### 解决方案：强化提示词

```python
PROMPT = f"""
系统预处理结果（必须在输出中准确反映）：
1. 非药物声明检测：{status}
   - 强制性设置: {value}
2. 标志检测：{status}
   - 强制性设置: {value}

请严格按照以下 JSON 格式输出，不要添加任何解释：
{{
    "is_or_not": {value},
    "reason": "...",
    "reference": "..."
}}

注意：
- 必须使用中文
- 必须返回纯 JSON，不要包含 markdown 标记
- reason 字段必须引用预处理结果中的具体数值
"""
```

关键点：
- 明确告诉 LLM 哪些结果是"预处理"得到的，必须遵循
- 提供完整的 JSON 示例
- 列出具体的注意事项

## 验证机制

建立多层验证：

```
1. 文件类型验证
   └── 检查 MIME 类型

2. 内容格式验证
   └── 检查 JSON 格式是否正确

3. 规则合规性验证
   └── 检查必填字段是否存在

4. 输出格式验证
   └── 检查 LLM 输出是否符合预期
```

错误处理：

```python
def create_error_response(reason: str) -> HealthFoodAnalysisResult:

    )
```

## 架构优化方向

当前问题暴露了架构的不足，考虑引入设计模式：

|------|------|

| 策略模式 | 处理不同类型的广告 |
| 模板方法 | 定义统一的分析流程 |

后续如果要支持更多广告类型，这些模式会很有用。

## 今日反思

今天主要在解决"不稳定"的问题。OCR 不稳定、LLM 输出不稳定，最后只能通过增加验证层和强化提示词来缓解。

一个重要的认识是：**LLM 不是确定性系统**。同样的输入可能得到不同的输出，这和传统编程完全不同。所以必须要有验证机制，不能假设 LLM 总是返回正确格式的结果。

另一个收获是提示词工程的重要性。"强制性设置"这几个字加上去，效果明显改善。提示词的每一个细节都可能影响输出质量。
