## 问题一：跨平台依赖冲突

项目的 `requirements.txt` 里有 `pywin32` 这个包，是Windows专用的。在Linux容器里装肯定会失败。

解决方案是在Dockerfile里预处理：

```dockerfile
# 删除Windows专用的包
RUN sed -i '/pywin32/d' requirements.txt

# 配置pip镜像源
RUN pip config set global.index-url https://mirrors.huaweicloud.com/repository/pypi/simple/

# 安装依赖
RUN pip install --no-cache-dir -r requirements.txt
```

这里 `--no-cache-dir` 可以减小镜像体积，不缓存下载的包。

## 问题二：构建速度优化

每次修改代码都要重新构建，太慢了。优化的核心是利用好Docker的层缓存。

**优化前**（每次都要重装依赖）：
```dockerfile
COPY . .
RUN pip install -r requirements.txt
```

**优化后**（只有requirements.txt变了才重装）：
```dockerfile
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
```

原理：Docker会缓存每一层的结果，只有当这一层的内容变化时才会重新执行。把依赖安装放在代码复制之前，就不会因为代码变化而重新安装依赖。

## 多阶段构建

进一步优化镜像体积，用多阶段构建：

```dockerfile
# 构建阶段
FROM python:3.10 AS builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --user -r requirements.txt

# 运行阶段
FROM python:3.10-slim
COPY --from=builder /root/.local /root/.local
WORKDIR /app
COPY . .
```

这样最终镜像只包含运行时需要的东西，不包含编译时的临时文件。

## Docker架构理解

今天也深入了解了Docker的架构：

```
Docker Client (CLI)
      ↓
Docker Daemon (dockerd)
      ↓
Container Runtime (containerd)
      ↓
Containers
```

几个关键概念：
- **镜像层**：每个Dockerfile指令创建一层，层可以被复用
- **联合文件系统**：把多层叠加成一个文件系统
- **Copy-on-Write**：容器只有在修改文件时才会复制，节省空间

## 网络模式

Docker有几种网络模式，今天都试了一下：

| 模式 | 特点 | 使用场景 |
|------|------|----------|
| bridge | 默认模式，容器有独立IP | 一般应用 |
| host | 直接使用宿主机网络 | 需要高性能网络的应用 |
| none | 没有网络 | 安全隔离场景 |
| overlay | 跨主机通信 | 集群部署 |

目前项目用的是默认的bridge模式，够用了。

## 运行时优化

添加了健康检查，确保服务正常运行：

```dockerfile
HEALTHCHECK --interval=30s --timeout=10s --start-period=5s --retries=3 \
  CMD curl -f http://localhost:8000/health || exit 1
```

这样Docker可以自动检测服务状态，有问题会自动重启。

## 今日反思

今天最大的体会是：**细节决定成败**。

Docker配置看起来就那么几行，但每一行都可能有坑。比如层缓存的顺序、跨平台依赖的处理、镜像源的选择，每个细节都会影响最终的效果。

另外一个感悟是：**先跑起来，再优化**。一开始不要追求完美的配置，先用最简单的方式跑起来，确认能工作，再逐步优化。如果一开始就想做到最好，很容易陷入"配置地狱"，半天跑不起来。

这几天配置Docker学到很多，感觉对容器化有了比较系统的理解。下周可以开始专注业务开发了。
