## 今天遇到的问题

今天在配置Docker环境时踩了不少坑。最头疼的问题是镜像拉取一直失败，网络超时让我反复尝试了很多次。后来才意识到，在国内环境下配置镜像加速器是必须的，这个经验以后一定要记住。

### 问题一：Docker镜像拉取失败

症状很明显——执行 `docker pull` 时总是超时。解决方法是配置国内镜像源：

```json
{
  "registry-mirrors": [
    "https://mirror.ccs.tencentyun.com",
    "https://registry.docker-cn.com"
  ]
}
```

配置完之后拉取速度明显快了很多。这里学到一个小技巧：**配置多个镜像源可以提高可用性**，当一个源不可用时会自动切换到下一个。

### 问题二：构建过程找不到文件

执行 `docker build` 时报错说找不到 `requirements.txt`，明明文件就在目录里。

排查后发现是**构建上下文**的问题。Docker构建时会把指定目录下的所有文件发送到Docker daemon，如果文件不在构建上下文中，Dockerfile自然就访问不到。

解决方法：
1. 确保所有需要的文件都在构建目录下
2. 使用 `.dockerignore` 排除不需要的文件，加快构建速度

### 问题三：Docker Desktop和VSCode插件的关系

一开始我以为VSCode的Docker插件可以独立运行容器，后来才明白它只是一个**管理界面**，底层还是依赖Docker Desktop（或Docker Engine）。

这几个工具的关系：
- **Docker Engine**：容器运行时，核心组件
- **Docker Desktop**：图形化管理工具，包含Docker Engine
- **VSCode Docker插件**：IDE集成，调用Docker Engine的API

## 技术要点整理

### Dockerfile最佳实践

多阶段构建可以显著减小最终镜像体积：

```dockerfile
# 构建阶段
FROM python:3.8-slim AS builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --user -r requirements.txt

# 运行阶段
FROM python:3.8-slim
COPY --from=builder /root/.local /root/.local
COPY . .
CMD ["python", "app.py"]
```

### 镜像层原理

每个Dockerfile指令都会创建一个新的镜像层。理解这一点对优化构建很重要：
- 把不常变化的指令放在前面（如安装系统依赖）
- 把经常变化的指令放在后面（如复制源代码）
- 这样可以最大化利用构建缓存

### 常见问题排查

| 问题 | 可能原因 | 解决方法 |
|------|----------|----------|
| 镜像拉取超时 | 网络问题 | 配置镜像加速器 |
| 构建时找不到文件 | 文件不在构建上下文 | 检查目录结构 |
| 容器启动失败 | 端口冲突或配置错误 | 查看容器日志 |

## 今日反思

今天花了大半天时间在环境配置上，虽然过程曲折，但收获很大：

1. **遇到问题先查文档**。一开始我习惯性地去搜索引擎找答案，结果看到的解决方案五花八门，有些还是过时的。后来直接看Docker官方文档，反而更清晰。

2. **理解原理比死记命令重要**。比如构建上下文的概念，一旦理解了，很多看似奇怪的报错就能解释了。

3. **配置要做好记录**。今天配置的镜像源、修改的配置文件，我都记在笔记里了。下次换电脑或者帮同事配置时就不用重新摸索。
