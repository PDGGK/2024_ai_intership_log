## 问题一：文件多次读取

同一个文件被读取多次，每次都重新 `await file.read()`，浪费资源。

### 解决方案

用上下文管理器统一管理文件：

```python
class AsyncFileManager:
    """异步文件管理器"""
    def __init__(self, file: UploadFile):
        self.file = file
        self.content = None
        self.copies = []

    async def __aenter__(self):
        """进入上下文时读取文件"""
        self.content = await self.file.read()
        return self

    async def __aexit__(self, exc_type, exc_val, exc_tb):
        """退出上下文时释放资源"""
        for copy in self.copies:
            copy.close()
        if self.file:
            await self.file.close()

    def create_copy(self) -> BytesIO:
        """创建文件副本"""
        copy = BytesIO(self.content)
        self.copies.append(copy)
        return copy
```

使用方式：

```python
async with AsyncFileManager(file) as manager:
    # 第一次使用
    result1 = process(manager.content)

    # 需要副本时
    copy = manager.create_copy()
    result2 = process(copy)
# 退出时自动释放资源
```

## 问题二：分块读取大文件

大文件一次性读取会占用太多内存。

```python
async def read_large_file(file: UploadFile, chunk_size: int = 8192):
    """分块读取大文件"""
    buffer = BytesIO()
    while True:
        chunk = await file.read(chunk_size)
        if not chunk:
            break
        buffer.write(chunk)
    buffer.seek(0)
    return buffer
```

或者用生成器：

```python
async def process_file_chunks(file: UploadFile, chunk_size: int = 8192):
    """使用生成器处理大文件"""
    while chunk := await file.read(chunk_size):
        yield chunk
```

## FastAPI 依赖注入

把文件管理器作为依赖注入：

```python
async def get_file_manager(file: UploadFile = File(...)):
    """文件管理器依赖"""
    async with AsyncFileManager(file) as manager:
        yield manager

@app.post("/analyze")
async def analyze_file(
    file_manager: AsyncFileManager = Depends(get_file_manager),
    batch_size: int = Form(default=5)
):
    """使用依赖注入处理文件"""
    content = file_manager.content
    # 处理逻辑...
```

好处：
- 资源管理自动化
- 代码更简洁
- 异常时也能正确释放

## 错误处理中间件

```python
class ErrorHandlingMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        try:
            response = await call_next(request)
            return response
        except Exception as e:
            logger.error(f"请求处理错误: {str(e)}")
            return JSONResponse(
                status_code=500,
                content={"detail": "内部服务器错误"}
            )
```

## 今日反思

今天主要在重构代码，没有新功能，但收获很大。

之前写代码只关注"能用"，没考虑资源管理。文件读了不关闭，BytesIO 创建了不释放，短时间看不出问题，长时间运行就会内存泄漏。Python 虽然有垃圾回收，但文件句柄这种系统资源还是要显式管理。

另一个收获是理解了上下文管理器的价值。`async with` 不只是语法糖，它保证了资源获取和释放的配对，即使出异常也能正确清理。这种"用完即走"的模式比手动 try-finally 更可靠。
