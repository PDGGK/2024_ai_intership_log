# 多模态模型显存管理与错误恢复

> **日期**: 2024-12-19
> **主题**: Qwen2-VL 显存溢出问题与批处理优化

## 今天遇到的问题

广告分析系统在处理大量图片时崩溃了：

```
CUDA out of memory. Tried to allocate 254.00 GiB.
GPU 0 has a total capacity of 79.11 GiB of which 14.88 GiB is free.
```

试图分配 254GB 显存，但 GPU 总共才 79GB...

---

## 问题分析

### 直接原因

多个请求同时发送到 VL 模型，每个请求都加载一张大图，显存瞬间爆炸。

### 根本原因

1. 没有显存监控
2. 没有批处理限制
3. xinference 对 Qwen2-VL 的批处理支持有限

---

## 解决方案

### 1. 显存监控

```python
class MemoryManager:
    def __init__(self):
        self.threshold = 0.8  # 80% 阈值

    async def check_memory(self) -> bool:
        """检查显存是否充足"""
        try:
            allocated = torch.cuda.memory_allocated()
            total = torch.cuda.get_device_properties(0).total_memory
            usage = allocated / total

            logger.info(f"显存使用率: {usage:.2%}")

            return usage < self.threshold
        except Exception as e:
            logger.error(f"显存检查失败: {str(e)}")
            return False

    def release(self):
        """主动释放显存"""
        torch.cuda.empty_cache()
        gc.collect()
```

### 2. 动态批处理

```python
class BatchProcessor:
    def __init__(self, memory_manager: MemoryManager):
        self.memory_manager = memory_manager
        self.batch_size = 1  # 从 1 开始，保守策略

    async def process_batch(self, items: List, processor: Callable) -> List:
        results = []
        current_batch = []

        for item in items:
            current_batch.append(item)

            if len(current_batch) == self.batch_size:
                # 检查显存
                if not await self.memory_manager.check_memory():
                    # 显存不足，减小批大小
                    self.batch_size = max(1, self.batch_size - 1)
                    logger.warning(f"显存不足，减小批大小到 {self.batch_size}")

                # 处理当前批次
                batch_results = await self._process_items(current_batch)
                results.extend(batch_results)
                current_batch = []

                # 处理完一批后释放显存
                self.memory_manager.release()
                await asyncio.sleep(0.1)

        return results
```

### 3. 错误恢复

```python
class ErrorRecoveryHandler:
    def __init__(self):
        self.max_retries = 3

    async def handle_error(self, error: Exception, context: dict):
        if isinstance(error, torch.cuda.OutOfMemoryError):
            return await self._handle_oom_error(context)
        else:
            return await self._handle_general_error(context)

    async def _handle_oom_error(self, context: dict):
        """处理显存溢出"""
        # 清理显存
        torch.cuda.empty_cache()
        gc.collect()

        # 等待资源释放
        await asyncio.sleep(1)

        # 用更小的批大小重试
        context['batch_size'] = 1
        return await self._retry_operation(context)
```

## 图像处理流水线

```python
class ImageProcessingPipeline:
    def __init__(self):
        self.memory_manager = MemoryManager()
        self.batch_processor = BatchProcessor(self.memory_manager)

    async def process(self, files: List[UploadFile]) -> List[Dict]:
        results = []

        for file in files:
            try:
                # 1. 文件验证
                if not await self._validate_file(file):
                    results.append(self._create_error_result(file, "验证失败"))
                    continue

                # 2. 图像预处理
                processed = await self._preprocess_image(file)

                # 3. 模型推理
                result = await self._analyze_content(processed)
                results.append(result)

            except Exception as e:
                logger.error(f"处理失败: {str(e)}")
                results.append(self._create_error_result(file, str(e)))

            finally:
                # 每个文件处理完都释放显存
                self.memory_manager.release()

        return results
```

## 今日反思

今天被显存问题折腾了一天。

最大的教训是：**GPU 资源是有限的，必须显式管理**。之前以为 GPU 和 CPU 一样，用完自动释放。实际上 GPU 显存管理比 CPU 内存复杂得多，PyTorch 的缓存机制会保留已分配的显存，需要手动 `empty_cache()`。

另一个收获是理解了"防御性编程"的重要性。显存监控、动态批大小、错误恢复，这些代码在正常情况下不会执行，但在极端情况下能救命。生产系统必须考虑各种边界情况。
