# Langchain-Chatchat 项目的 Docker 化部署

> **日期**: 2024-11-20
> **主题**: ARM架构下的容器化部署实践

---

## 背景

今天尝试在 M3 Max MacBook 上部署 Langchain-Chatchat 项目。这是一个知识库问答项目，集成了 LangChain 和各种大语言模型。部署过程中遇到了不少 ARM 架构相关的坑。

---

## 核心问题：ARM64 vs AMD64

M系列芯片是 ARM64 架构，但大多数 Docker 镜像是为 AMD64（x86）架构构建的。直接运行会报错或者性能很差（通过 Rosetta 模拟）。

解决方案是明确指定平台：

```dockerfile
FROM --platform=linux/arm64 python:3.10
```

或者在构建时指定：

```bash
docker build --platform linux/arm64 -t myapp .
```

另一个更好的方案是使用多架构镜像（multi-arch images），这样 Docker 会自动选择合适的架构。

---

## 依赖处理

这个项目原本是在 Windows 上开发的，requirements.txt 里有 `pywin32` 这种 Windows 专用包。在 Linux 容器里肯定装不了。

处理策略：

```dockerfile
# 构建阶段预处理依赖
FROM python:3.10 AS builder
WORKDIR /app
COPY requirements.txt .

# 移除 Windows 专用包
RUN sed -i '/pywin32/d' requirements.txt

# 安装依赖
RUN pip install --user --no-cache-dir -r requirements.txt
```

---

## 多阶段构建

为了减小最终镜像体积，采用多阶段构建：

```dockerfile
# 构建阶段
FROM python:3.10 AS builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --user -r requirements.txt

# 运行阶段
FROM python:3.10-slim
COPY --from=builder /root/.local /root/.local
COPY . .

ENV PATH=/root/.local/bin:$PATH
CMD ["python", "main.py"]
```

这样最终镜像不会包含编译时的临时文件，体积能减小很多。

## 运行时配置

```yaml
# docker-compose.yml
services:
  chatchat:
    build:
      context: .
      platform: linux/arm64
    ports:
      - "7860:7860"
    environment:
      - PYTHONPATH=/app
      - PYTHONUNBUFFERED=1
    volumes:
      - ./config:/app/config
      - ./models:/app/models
```

几个要点：
- `PYTHONUNBUFFERED=1` 让日志实时输出，方便调试
- 配置和模型文件用 volume 挂载，方便更新

## 遇到的其他问题

### 1. BuildKit 缓存

启用 BuildKit 可以加速构建：

```bash
DOCKER_BUILDKIT=1 docker build -t myapp .
```

BuildKit 支持并行构建和更智能的缓存机制。

### 2. 用户权限

容器内创建的文件默认是 root 权限，在宿主机上操作不方便。解决方法：

```bash
docker build \
  --build-arg USER_ID=$(id -u) \
  --build-arg GROUP_ID=$(id -g) \
  -t myapp .
```

## 今日反思

今天最大的收获是理解了 ARM 和 x86 架构差异对 Docker 部署的影响。

以前在 Intel Mac 上用 Docker，从来没遇到过架构问题。换了 M 系列芯片后，才发现很多镜像不兼容。好在 Docker 对多架构的支持越来越好，大多数官方镜像都提供了 ARM 版本。

另一个体会是：**部署问题往往比开发问题更复杂**。写代码可以在本地调试，但部署涉及环境、网络、权限等各种因素，需要更系统的排查思路。

这次部署经验对后面的工作很有价值，很多坑踩过一次就知道怎么避开了。
